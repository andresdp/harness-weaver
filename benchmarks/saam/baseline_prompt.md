# SAAM baseline prompt (WRCS adaptation)

This prompt adapts the existing `case-studies/architecture-eval/SAAM/prompt.txt` for a supplied structured case. The source prompt's SAAM method guidance is retained; instructions about extracting a PDF, populating paper metadata, IEEE 42010 extraction, and the fixed extraction template do not apply to this already extracted WRCS case and are omitted. This adaptation is the baseline arm's disclosed instruction bundle.

Evaluate the supplied software architecture using the Scenario-Based Architecture Analysis Method (SAAM). Focus on modifiability by analyzing the supplied scenarios, distinguishing direct support from support requiring architectural modification, and identifying scenario interactions only when the supplied architecture evidence supports them.

Use only the supplied evaluation inputs and the six supplied source scenarios. Preserve scenario IDs and source wording. Do not invent facts, architecture components, scenario relationships, or missing evaluation results. If the input does not support a conclusion, leave the corresponding collection empty or state the uncertainty in the relevant narrative field. Treat the case as partial: only six of fifteen scenarios are represented. Make no claims about absent scenarios.

Provide a structured SAAM report with: the six scenarios; a Direct/Indirect classification for each when supported; scenario evaluations with affected components and change extent only when supported; interactions only when evidence supports shared components or interaction effects; overall strengths and weaknesses; and recommendations grounded in the supplied architecture. Keep source-supported observations separate from assumptions or extraction-level inferences. Use an empty list rather than fabricating unsupported items.

Attach at least one `evidence_refs` entry to every classification, scenario evaluation, interaction, strength, weakness, modifiability assessment, and recommendation. Each entry must contain `source_pointer`, an RFC 6901 JSON Pointer that resolves within the supplied evaluation-input object (the JSON object in the user message, not the outer report) to a non-empty scalar value such as a string or number. Cite leaf values, never an object, list, null, or empty string. Use only paths and values actually supplied. For example, the supplied case has paths such as `/system_context/system_name`, `/scenario_inputs/0/scenario_text`, and `/architecture_description/architectures/0/key_components/0/component_name`; do not copy a path that is not present in this input. Do not cite evaluator-only reference outputs. If a claim cannot be supported by a supplied input field, omit that claim rather than inventing a citation.
