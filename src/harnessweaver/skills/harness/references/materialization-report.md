# Materialization report template

Every target writes `materialization-report.md` in its output directory. It is the fidelity record: what the HarnessSpec became in this runtime and what did not survive. Copy this template.

```markdown
# Materialization report: <spec id> → <target>

- Spec: <path>, version <spec_version>, sha256 <digest>
- Target: <claude | deepagents>; host: <claude-code | harnessweaver stage host | existing app: name@revision>
- Generated by: harness skill <digest or revision>; coding agent <name and version>; model <id>
- Date: <YYYY-MM-DD>; gate answers: see design-notes.md (sources: live / answers file / unconfirmed)

## Mapping

| Spec element | Kind | Target construct (path) | Status | Note |
|---|---|---|---|---|
| <stage id> | stage | <file or construct> | mapped / approximated / unsupported | <what changed in meaning, if anything> |
| <role id> | role | ... | ... | ... |
| <artifact id> | artifact | ... | ... | ... |
| <verification id> | verification | ... | ... | ... |
| <gate id> | human gate | ... | ... | ... |
| semantic state | methodology state | ... | ... | ... |

## Decisions

| Decision | Choice | Rationale | Gate |
|---|---|---|---|

## Domain skills

| Source skill | Target path | Copied verbatim / adapted (what) |
|---|---|---|

## Manual setup required

Anything a person must do before the bundle runs (credentials, host changes, tool installation).

## Not verified

What this generation did not check (e.g., no execution run, no trigger tests, schema agreement not checked).

## Suggested smoke test

One minimal run and what to check.
```

Rules:

- List **every** stage, role, artifact, verification and human gate in the spec. A missing row counts as an unsupported mapping.
- "Approximated" means the construct exists but its guarantee is weaker. For example, typed handoffs that are only instructed in a skill, not enforced by the runtime.
- Do not edit the spec to make a row look mapped.
